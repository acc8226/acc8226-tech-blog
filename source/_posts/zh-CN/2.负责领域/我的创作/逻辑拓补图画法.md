## 物理拓扑 vs 逻辑拓扑

**物理拓扑：硬件实际怎么接线（看得见的网线、端口、设备）** **逻辑拓扑：网络流量、VLAN、IP 网段怎么走（看不见的数据通路）**

> 很多项目文档会两张图一起交付：**物理拓扑给机房施工、布线、硬件运维；逻辑拓扑给网络配置、安全策略、业务排查**

### 一、核心对比表

表格

| 项目 | 物理拓扑（Physical） | 逻辑拓扑（Logical） |
| -------- | --------------------- | ------------ |
| 关注点   | 硬件设备、物理线缆、端口、机柜位置 | 网段、VLAN、路由、业务访问关系 |
| 画什么   | 交换机哪个端口，网线 / 光纤，光模块，服务器网卡、IPMI 口，存储光纤线 | VLAN、网关、IP 网段、防火墙策略、路由走向、业务访问关系   |
| 线条含义 | 代表**一根真实存在的网线 / 光纤**，一条线对应一根实物线缆 | 代表**数据通信通路**，一根物理网线上面可以跑多个逻辑 VLAN |
| 使用场景 | 机房布线、上架、故障查线、搬迁、硬件更换 | 防火墙放通策略、业务调试、IP 规划、安全评审 |
| 典型特点 | 线缆数量多，双网卡多链路会画两条实线；看重端口编号 `G0/1` | 图上线路更少，不关心物理端口，重点标注网段 / VLAN 号 |

### 二、举个最直观例子

一台接入交换机，**一根网线**连到核心交换机：

- **物理拓扑**：画 1 根实线，标注：`SWA G0/1 ↔ Core G0/1 光纤`（就是这根真实光纤）
- **逻辑拓扑**：这同一条物理链路上承载 VLAN10（Web 业务）、VLAN20（数据库）、VLAN30（管理）。逻辑图上会画出 3 条逻辑通路，代表 3 个网段的数据从这里通行，但**不会画 3 根物理线**。

> 关键点：**一根物理线缆，可以承载多条逻辑通道**，这就是两者最大区别。

### 三、各自图纸里重点标注内容

#### ✅ 物理拓扑图（硬件布线图）

1. 设备物理位置：机柜号、设备在第几 U
2. 端口编号：`G0/0`、`10G0/1`、IPMI 口、HBA 卡口
3. 介质：六类网线 / 单模光纤、光模块
4. 链路：双活、主备的两根独立物理线缆（必须都画出来）
5. 区分：业务网卡、存储网卡、管理 IPMI 网卡，三套独立物理网线

> 适合：弱电施工、机房巡检、拔线排查硬件断连、设备搬迁。

#### ✅ 逻辑拓扑图（业务网络图）

1. VLAN ID、网段 / 子网、网关 IP
2. 业务分区：DMZ 区、业务区、数据库区、管理区（安全域）
3. 访问关系：Web 能不能访问 DB，外网能否访问 Web
4. 路由、防火墙策略、负载均衡虚拟 IP（VIP）
5. **不写物理端口，不关心一根线还是两根线**

> 适合：方案汇报、等保测评、安全评审、业务故障排查（网络不通、策略拦截）

### 四、什么时候画哪张？

1. **项目招投标、立项、等保、方案汇报**：优先 **逻辑拓扑**（领导、评审专家想看业务分区和数据流，不关心一根根网线）
2. **机房实施、上架布线、运维台账、硬件检修**：必须 **物理拓扑**，运维要按图找线、找端口
3. 正式信息化项目交付标准：**两张图都要**

元素要规范，例如 ciscio、华三、锐捷
